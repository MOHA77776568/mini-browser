# مِدار — Mini Browser

متصفح سطح مكتب بواجهة عربية، مبني على Electron وChromium. يفتح مواقع الإنترنت داخل التطبيق، ويدعم علامات التبويب، البحث عبر Google، الرجوع والتقدّم، إعادة التحميل، المفضّلة والتنزيلات. يدعم صفحات الويب التفاعلية وفيديو HTML5، ويطلب موافقتك قبل منح المواقع الأذونات المدعومة مثل الكاميرا والميكروفون.

## الاستخدام على Windows

على **Windows 10 أو 11 بنظام x64**، نزّل [النسخة المحمولة Mini-Browser-Windows-x64.exe](https://github.com/MOHA77776568/mini-browser/releases/download/v1.0.3/Mini-Browser-Windows-x64.exe) ثم شغّلها بالنقر المزدوج؛ لا تحتاج إلى تثبيت. يتوفر أيضًا [مثبّت Windows](https://github.com/MOHA77776568/mini-browser/releases/download/v1.0.3/Mini-Browser-Setup-Windows-x64.exe). تتوفر بصمات الملفين في [SHA256SUMS.txt](https://github.com/MOHA77776568/mini-browser/releases/download/v1.0.3/SHA256SUMS.txt).

اكتب رابطًا أو عبارة بحث في شريط العنوان، أو استخدم مربع البحث في الصفحة الرئيسية. يفتح `Ctrl+T` تبويبًا جديدًا، و`Ctrl+L` شريط العنوان، و`Ctrl+W` يغلق التبويب، و`Ctrl+D` يضيف الصفحة إلى المفضّلة. زر التنزيلات يفتح مجلد التنزيلات.

تُحفظ ملفات تعريف الارتباط وبيانات المواقع والمفضّلة محليًا داخل مجلد `userData` الخاص بالتطبيق في حساب المستخدم، وتبقى بعد إغلاقه. هذا ليس وضع تصفّح خفيًا، ولا يحتاج تشغيل التطبيق إلى مفاتيح API أو أسرار.

## التطوير

ثبّت **Node.js 22.12 أو أحدث**؛ يُنصح بالإصدار 24. من مجلد المشروع:

```sh
npm ci
npm exec -- install-electron --no
npm start
```

يفتح الأمر الأخير نافذة Electron فعلية على جهاز يدعم واجهة رسومية؛ التطبيق لا يعمل كمعاينة ويب على `localhost`.

لتشغيل الاختبارات:

```sh
npm test
npm run test:e2e
```

الأمر الأول يفحص معالجة العناوين، والثاني يجري اختبارًا وظيفيًا داخل Electron ويتطلب جلسة سطح مكتب. تُحفظ لقطات الاختبار في `artifacts`.

## إنشاء نسخة Windows

لإنشاء نسخة محمولة من Windows أو من بيئة Linux السحابية:

```sh
npm exec -- electron-builder --win portable --x64 -c.win.signAndEditExecutable=false --publish never
```

النسخة المحمولة غير موقّعة رقميًا، وتحافظ على إعدادات عزل التطبيق المعتادة.

لإنشاء مثبّت NSIS على Windows:

```sh
npm exec -- electron-builder --win nsis --x64 --publish never
```

ينتج المثبّت داخل `dist` باسم `Mini Browser Setup 1.0.3.exe`. يتطلب بناء مثبّت NSIS من Linux وجود Wine، وهو غير متاح في البيئة السحابية الحالية.

يمكن أيضًا تشغيل سير العمل `Build Windows installer` يدويًا من تبويب **Actions** في GitHub بعد رفع المشروع إلى المستودع. يبني المثبّت على Windows، ويُرفقه بنتائج التشغيل للتنزيل، دون إنشاء إصدار أو نشره تلقائيًا.

سير العمل `Build Windows release assets` يشغّل الاختبارات الوظيفية على Windows، ويبني النسخة المحمولة والمثبّت، ثم يرفقهما مع بصمتي SHA-256 بالإصدار الموجود. يمكن تشغيله يدويًا مع اسم وسم الإصدار؛ يلزم وجود مسودة الإصدار ووسمه مسبقًا. ينشر مسؤول المستودع المسودة بعد التحقق من الملفات.

## البيئة السحابية

```sh
npm run test:cloud
```

يشغّل هذا الأمر الاختبارات على شاشة Xorg افتراضية باستخدام برنامج التشغيل `dummy` و`xauth` المثبّتين في البيئة. بسبب قيود مساحات أسماء المستخدمين في هذه البيئة، يُعطّل عزل نظام التشغيل الخاص بـ Chromium داخل الاختبار المؤقت فقط. يظل التشغيل العادي للتطبيق بإعدادات العزل الأصلية.

إعداد الشبكة السحابي المقيّد قد يمنع الوصول إلى مواقع عامة. لإتاحة وجهات إضافية، عدّل إعدادات شبكة البيئة السحابية ثم أعد الاختبار؛ هذا القيد يخص البيئة السحابية.

إذا كان الاتصال يمر عبر وكيل المنصة وظهر `ERR_CERT_AUTHORITY_INVALID`، فتحقّق أولًا من وجود شهادة CA العامة التي توفرها المنصة عبر `NODE_EXTRA_CA_CERTS` في مخزن NSS في `~/.pki/nssdb`، ومن إمكانية الكتابة إلى هذا المجلد؛ يحتاج NSS إلى الكتابة لتهيئة قاعدة بياناته. في البيئة الحالية كانت الشهادة موجودة بالفعل، واحتاج الاختبار إلى صلاحية كتابة محددة لهذا المجلد. استخدم `certutil` من حزمة `libnss3-tools` لفحص الثقة، واستورد الشهادة فقط إذا كانت مفقودة، ثم أعد الاختبار مع إبقاء التحقق من TLS مفعّلًا.

يدعم شريط العنوان روابط **HTTP وHTTPS**. دعم فيديو HTML5 لا يضمن تشغيل جميع خدمات الفيديو المحمية بـ DRM، كما أن دعم إضافات Chrome غير متاح حاليًا.
